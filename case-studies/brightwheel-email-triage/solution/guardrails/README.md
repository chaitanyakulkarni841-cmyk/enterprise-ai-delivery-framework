# Guardrails and enforcement evidence

[Solution index](../README.md)

Upload a control policy and an enforcement map: risk → rule → actual enforcing module/system → safe failure response → verifying test → owner.

Cover approved routing destinations, human review before external replies, invalid output, urgency/escalation, missing context, untrusted instructions, input limits, permissions, privacy, and retries. Mark proposed controls separately from implemented/tested ones.

A YAML policy or prompt sentence is not proof of enforcement. Do not claim complete protection from prompt injection or use unvalidated self-reported confidence as the only approval signal.
